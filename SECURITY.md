# Private security reporting

For a security vulnerability, use **nivotion → Security → Advisories → Report a vulnerability**, the product repository's GitHub **private** reporting form. [Report a vulnerability privately](https://github.com/nivotion/nivotion/security/advisories/new).

Private vulnerability reporting is enabled for the product repository. If the button is unavailable, wait for the private channel; do not put vulnerability details, exploits, secrets or private data in public Issues or Discussions.

Normal bugs belong in **nivotion-feedback Issues**; open feedback belongs in **nivotion-feedback Discussions**. A suspected security vulnerability is different and must remain private.

Do not upload private or sensitive CSV contents. If data is needed, create a tiny synthetic CSV that reproduces the issue. Redact names, emails, customer data, local paths, tokens and private business data from screenshots, logs and attachments.

Include the affected version/build and a concise description of the impact. No response-time guarantee is made. Formula-like values in CSV exports are not sanitized; review outputs before opening them in spreadsheet software.
